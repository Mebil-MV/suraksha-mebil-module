# Contributing to Suraksha WebGIS

## General workflow

Do not directly push changes to `main`.

1. Create a feature branch.
2. Make changes on your feature branch.
3. Commit your changes with a meaningful message.
4. Push your branch to GitHub.
5. Open a Pull Request.
6. Wait for review/testing before merging.

## Branch naming

Use descriptive names such as:

feature/platform
feature/exposure
feature/gis
feature/ml-cv
feature/crisis
feature/response-recovery

## Commit messages

Examples:

feat: add SOS event schema
feat: add exposure sample data
fix: correct incident validation
docs: update architecture documentation

## Data

Do not upload large raw datasets unless explicitly agreed.

Use sample/mock data where possible.

## Module documentation

Each module should document:

- Objective
- Inputs
- Outputs
- Data format
- Dependencies
- How to run the module
- Integration requirements
